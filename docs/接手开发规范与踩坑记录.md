# 接手开发规范与踩坑记录

这份说明帮助下一位 Agent 先理解状态所有权，再改 hook。当前工作区保留了完整 Git 仓库和未提交的功能改动；接手第一步应查看 `git status --short` 与 `git diff`，不要清理、回滚或覆盖这些现存改动。

## 仓库布局

| 路径 | 责任 |
| --- | --- |
| `app/src/main/java/.../hooks/systemui/` | SystemUI 输入、BackPanel、WM Shell 协作、动画背景 |
| `.../hooks/miuihome/` | MiuiHome 手势 owner、桌面状态镜像、返回桌面动画与 preview |
| `.../hooks/systemserver/` | Activity opt-in、系统窗口/返回桌面兼容边界 |
| `.../hooks/hotreload/` | API 102 热重载、旧 hook id 映射与补装 |
| `.../hooks/core/HookRuntimeCore.java` | 跨进程常量、状态和基础偏好监听 |
| `.../activity/` | Miuix Compose 设置页、应用选择、手势区域 |
| `.../PredictiveBackPreferences.java` | 所有跨进程设置 key、默认值、范围 clamp |
| `hidden-api/` | 仅 Android boot classpath 隐藏 API 的 compile-only stub |
| `refs/aosp_back/` | 已纳入版本控制的 AOSP 对照代码片段；并非所有文件均与目标 tag 逐字一致 |
| `AGENTS.md` | 必须遵循的长篇架构不变量、禁止路径及开发要求 |

项目使用 Java 编写 hook/runtime，Kotlin 编写现有 UI。不要为文档整理而把已划分到不同 runtime 的动画状态机合并回一个巨型类；新增功能应放进责任相符的模块，并更新本文代码地图。

## 重要架构约束

### 手势输入只有一个决定者

BackPanelController 决定真实状态、阈值、commit/cancel 和系统触感。模块 overlay 只能画皮肤，不处理原始输入。MiuiHome 的 GestureStub 继续作为物理 DOWN/redirect owner；SystemUI monitor 只有在 accepted-DOWN 身份匹配时才可接手。

禁止用额外可触摸 overlay 屏蔽桌面或 App，也不要把事件重放给另一个进程。状态通知须显式发给正确包，并校验 sender UID；状态过期时清除/拒绝，而非猜测焦点。

### Looper / executor 所有权

- 输入和 BackPanel 事件在 SystemUI 输入线程处理。
- Shell transition、tracker、runner 状态由 Shell executor 拥有。
- MiuiHome `WindowElement`、`StateManager`、Launcher View 和 preview wallpaper 由 MiuiHome main Looper 拥有。
- SystemServer 的 Activity/WindowContainer 字段不得从 SystemUI input Looper 直接读取。

跨线程只发布带 immutable identity、代数和明确生命周期的快照。不要用 sleep、循环 polling、时间窗或 process-global flag 修复某次对象竞态；会把前一段动画、后一段手势和新 Activity 混为一谈。

### 反射与 API 边界

- 先在配置的 JADX/MCP 源码里确认 HyperOS 目标 build 的方法签名、字段和调用点，再加 hook。
- SystemUI、WM Shell、MiuiHome 私有实现类在目标进程 ClassLoader 中；不能新增它们的 compile-only Java 类或静态引用，继续按真实 ClassLoader 反射。
- 热路径的 `Method` / `Field` 应缓存。使用确定的类/签名优先；签名兜底必须排除歧义并失败关闭。
- `hidden-api/` 只放 Android boot classpath API 的 stub；LSPosed 接口保持 `io.github.libxposed:api:102.0.0`。
- 用现代 libxposed API 102；`PackageLoadedParam` 是 `getDefaultClassLoader()`，日志使用 module logger。

### Hook 生命周期和热重载

API 102 配置 `autoHotReload=true`。hook ID 是生命周期键。新增/改名/删除 hook 时，一并更新普通安装、旧 ID 替换映射、presence tracking 和缺失 hook backfill。只有 `replaceHook(...)` 成功后才能把旧 hook 标成已替换。

`onHotReloading(...)` 要先释放模块创建的输入 monitor、overlay window、receiver 和未完成 session，再保存明确需要恢复的状态。`onHotReloaded(...)` 不得重复注册 monitor、callback 或 receiver。防止旧 Launcher / Activity 的延后回调覆写新实例状态。

## 踩过的坑与修改时检查项

### 1. 用小米原始下发状态代替“当前 Activity / 桌面焦点”猜测

MiuiHome 的 Activity 栈中可能留有 Launcher，但它不代表 Launcher 正占据屏幕。桌面文件夹由 Launcher 自己处理返回；桌面、桌面抽屉/编辑、控制中心、小窗等属于不同的 Back owner。应从真实窗口、SystemUI 状态和启动器状态回调镜像需要的最小状态，不做焦点轮询。

小窗刚从全屏缩小时，normal-window 集合包含紧凑态快照；不能将“集合非空”直接视作“放大态”。也不能只看焦点，因为放大态小窗回到桌面再回来时焦点回调会变。字段缺失/过渡态应 fail closed，实机验证窗口状态字段对 ROM 的含义。

### 2. “可以拉出”与“提交返回”不是一个条件

MOTION DOWN 是候选；通过方向意图和距离门限才 pilfer；最后的提交由原生 panel/tracker 或确切 Native OPEN merge 决定。不能用最终坐标重算已取消的释放，也不能拦截 `setTriggerBack(false)`。

输入 spy 的 accepted token 需要精确匹配 MotionEvent、display、edge、SystemUI arbiter generation。只按时间和边缘猜测容易把上一段动画或旧窗口 token 用到新手势。

### 3. Android 高斯模糊需画在正确的 ViewRoot/Surface 所有者

在屏幕最下方放一个模糊 overlay 常会得到纯色层：模糊 drawable 看的是自身 Window buffer，不会自动采样底下所有 Surface。当前 AOSP 返回小球做法复用原生 BackPanel ViewRoot 的 background blur drawable，原生 arrow 保留自身绘制；不要恢复一个顶层独立球/黑色遮罩。

背景色覆盖透明度与原生面板出现/消失 alpha 是不同参数。透明度调节只改 material tint，不能覆盖系统 alpha，否则会出现球消失延迟或取消后黑层滞留。颜色、模糊半径应在手势开始时快照，绘制帧只用缓存对象。

### 4. Wallpaper 背景需正确的层序和动画清理

壁纸是在两个 Activity 后面的背景，不应盖掉下层 Activity 或拿一个静态图片代替前景任务。System Surface 层序和 transaction 的提交边界非常重要；成功和取消都需要释放 module-owned blur/wallpaper surfaces。壁纸快照按 Wallpaper ID 缓存，禁止每帧解码或复制。

源码当前对 AOSP 颜色填充有效，HyperOS 原生 slide 颜色仍独立；不要用 UI 开关混淆这两套处理路径。小米 return-home preview 对原生 app/Home wallpaper 参数做了状态移交，应按 session identity 恢复，不能无条件覆盖新动画。

### 5. Activity 进入中打断不能混用两种返回协议

SystemUI/Shell predictive-back 要交给其原始 tracker、runner 和 transition lifecycle。小米 Activity OPEN 的 legacy interruption 要走小米 native merge path，提交只发一次普通 BACK。不要既做 AOSP exit 又发旧 BACK；就会出现两套视觉完全不同的动画先后执行。

Launcher-to-App OPEN 归 MiuiHome remote-animation path，不一定会进入 `DefaultTransitionHandler.startAnimation(...)`。Android 里 Activity OPEN 与 launcher 图标启动不是同一入口，不能靠一个“全局检查正在进入动画”的 hook 覆盖。

### 6. 返回桌面 runner callback 次序不固定

Shell callback 和 remote runner 是两个 Binder endpoint，允许独立到达。只保留当前 generation 最新进度和至多一个 terminal action，按身份消费一次。Spring、Shell runner 和任务 Surface 共享提交/取消边界；不能在局部 preview 结束时抢先清掉仍在播放的 Shell transition。

Activity / TaskFragment / wallpaper 的 prepared roles、fixed rotation 和 closing leash 都有特定组合；只对验证过的精确 shapes 改字段。transaction 需要在原生 transaction 仍未 apply 时合并，不能先暴露一帧全屏目标。

### 7. 热路径性能

- 绝不记录每个 MOVE；不要在日志开关关闭时仍构造长日志字符串。
- 不在 MOVE 期间读取 RemotePreferences、查包、读取窗口焦点或重复解析反射。
- 动画绘制中复用 Path、Paint、Rect、Bitmap 和 cached reflection handle。
- 不加定时器、轮询线程、重复 manager 查询或 overlay 只为修复偶发状态。
- 一个独立功能最多在必要生命周期边界工作；退出/取消后清掉 module-owned 对象。

### 8. 音效/震动系统只能选一条反馈链

AOSP 原生 panel 触感、HyperOS 原生效果和模块自定义 vibrator composition 会相互叠加。UI 需互斥；不要通过禁用整个 View 的 haptics 抑制某一个 effect，除非状态作用范围已经证明只覆盖被隐藏面板。每个设备验证 primitive 支持和实际马达强度。

## 项目规范

1. 静态作用域保持 `com.android.systemui`、`com.miui.home`、`system`。不要把所有 opt-in App 加入 scope，也不要新增系统范围 hook，除非日志/源码证明现有边界不足。
2. 先看目标版本源码和用户日志，再决定添加 hook。遇到不确定状态 fail closed，让系统既有路径继续工作。
3. 模块诊断统一走 LSPosed/module log；不使用 `android.util.Log` 写 module 日志。
4. 默认关闭详细诊断。必要日志记录 stream 边界、route 决策、生命周期和异常身份变化，禁止逐帧记录。
5. 保持 hook 安装、替换、热重载清理成套更新；代码、行为、诊断和文档变更按功能拆成易审阅的提交。
6. `reports/` 按 `reports/NNN-short-topic/README.md` 保存本地逆向与实验记录，保持 ignored，不提交。工作区整理时不要把 JADX 解包 APK、日志包、APK、测试输出和构建缓存当项目源码搬运。
7. 不提交 keystore、签名密码或 `keystore.properties`；保留 Gradle 现有签名配置读取约定。
8. `versionCode` 来自 Git commit 数。产生用户可安装 APK 时，按 `AGENTS.md` 先提交确认的源代码，再 clean build 对应 release variant；实机确认之前不把测试包当正式发布。
9. 用户明确要求验证/构建时，再运行匹配的 lint/build/device workflow；任务只要求文档/整理时不需要额外跑测试。
